# 一人公司 AI 工作系统 — 框架设计文档 v2.1

> 目标：搭建一套基于 Claude Code + GitHub 的工作系统，让 AI 成为你公司的"第二大脑"，解决上下文丢失和工作碎片化问题。

---

## 一、核心设计理念

### 1.1 你的痛点

| 痛点 | 根因 | 解决思路 |
|------|------|----------|
| 每次新开项目要重复输入背景 | Claude Code 无持久记忆 | 用 CLAUDE.md 作为全局记忆入口 |
| 多产品之间没有统一管理 | 缺少项目元数据和状态追踪 | 统一的项目注册表 + 状态面板 |
| 工作角色切换混乱（开发/运营/SEO…） | 一人多角色没有流程化 | 按角色建立标准工作流和 prompt 模板 |
| 经验/决策没有积累 | 做完就忘，没有复盘沉淀 | 决策日志 + 技能库 + 复盘模板 |

### 1.2 设计原则

1. **CLAUDE.md 是唯一入口** — Claude Code 启动时自动读取，一切从这里开始
2. **代码和管理分离** — 每个产品是独立 GitHub 仓库，全局管理集中在 work-system 仓库
3. **写给 AI 看的文档** — 所有 .md 文件首先服务于 Claude Code 的理解，其次才是人类阅读
4. **最小启动，渐进生长** — 先建骨架，在实际使用中填充和迭代

## 二、整体架构

### 2.1 仓库分离策略

系统由 **1 个总部仓库 + N 个项目仓库** 组成：

- **work-system 仓库**（总部）：战略、运营、决策、技能库等全局性内容
- **各项目仓库**（执行层）：代码 + 项目级 CLAUDE.md + 项目文档

Claude Code 根据你当前所在目录自动加载对应的 CLAUDE.md，实现无缝上下文切换。

## 三、关键文件内容设计

### 3.1 总部 CLAUDE.md（work-system 仓库根目录）

```markdown
# CLAUDE.md — [你的名字]的一人公司工作系统

## 你是谁
你是我（[你的名字]）的 AI 开发伙伴和业务助手。我运营着多个面向海外用户的 AI 图像工具网站，
目标是构建一个可持续盈利的一人公司。

## 我的业务全貌
- 主站：[项目A] ([域名]) — 通用 AI 绘图平台
- 专题站：[项目B] ([域名]) — Gemini 图像生成
- 垂直站：宠物肖像、涂色页、卡通化等细分工具站
- 商业模式：Google AdSense + 免费增值

## 仓库地图
| 项目 | 仓库路径 | GitHub |
|------|----------|--------|
| [项目A] | ~/Documents/projects/cubistai | github.com/[user]/cubistai |
| [项目B] | ~/Documents/projects/nanobananapix | github.com/[user]/nanobananapix |

| 卡通化 | ~/Documents/projects/cartoon-yourself | github.com/[user]/cartoon-yourself |

## 技术栈
- 前端：Next.js (App Router) + Tailwind CSS
- 部署：Vercel
- AI API：Replicate, Google Gemini, 各类 SDXL 模型
- 代码托管：GitHub

## 工作规则
1. 做项目开发时 → cd 到对应项目仓库，读取项目级 CLAUDE.md

2. [示例] [项目A] 新增 3 个 landing page
3. [示例] 优化全站 Core Web Vitals
```

## 六、实施步骤

### 第一步：立即做（30 分钟）

1. 在 GitHub 创建 `work-system` 仓库
2. 克隆到本地 `~/Documents/projects/work-system/`
3. 创建根 CLAUDE.md 并填入真实信息
4. 创建控制面板.md 并列出当前所有项目

### 第二步：本周做

1. 为每个已有项目仓库添加 CLAUDE.md 和 docs/ 目录
2. 建立 00-全局资源/ 下的技术栈文档
3. 把过去的开发经验写入 05-技能库/
4. 填写 02-运营中心/社交媒体/策略.md，明确人设和平台规划

### 第三步：持续做

1. 每次开发后更新项目的 docs/迭代日志.md
2. 每做一个重要决策写决策日志
3. 每周花 10 分钟更新控制面板
4. 遇到可复用的经验就沉淀到技能库
5. 每次迭代后提炼社媒素材，每周复盘社媒数据

## 七、与 Claude Code 的配合要点

### 7.1 CLAUDE.md 层级机制

Claude Code 自动读取当前工作目录的 CLAUDE.md：

| 你的位置 | Claude Code 读到 | 适合做什么 |
|----------|------------------|------------|
| ~/Documents/projects/work-system/ | 全局 CLAUDE.md | 战略规划、运营、社媒、决策 |
| ~/Documents/projects/cubistai/ | [项目A] 的 CLAUDE.md | 项目开发、Bug 修复 |
| ~/Documents/projects/coloring-pages/ | 涂色页的 CLAUDE.md | 项目开发 |

项目级 CLAUDE.md 通过路径引用总部仓库，需要时 Claude Code 可以跨仓库读取。

### 7.2 让 Claude Code 主动维护文档

在 CLAUDE.md 的工作规则中明确要求 Claude Code 完成任务后自动更新相关文档（迭代日志、已知问题等）。系统会随使用自然生长。

### 7.3 CLAUDE.md 精简原则

- 总部 CLAUDE.md：< 200 行，只放全局信息和导航
- 项目级 CLAUDE.md：< 150 行，只放 Claude Code 开发时需要的信息
- 详细内容放在 docs/ 下的独立文件中，按需读取

### 7.4 .gitignore 建议

项目仓库中的 CLAUDE.md 和 docs/ 建议**纳入版本管理**，这样：
- 文档变更有历史记录
- 多设备同步
- 回溯任何时间点的项目状态

## 八、与参考方案（Roland）的差异

| 维度 | Roland 方案 | 本方案 |
|------|------------|--------|
| 架构 | 单一文件夹系统 | 总部仓库 + N 个项目仓库（GitHub 原生） |
| 侧重 | 内容创作者 | 产品开发者（多产品管理） |
| 记忆 | 通用记忆库 | 分层 CLAUDE.md（全局 + 项目级） |
| 技能库 | 按内容/商业/通用 | 按开发/SEO/运营（贴合你的角色） |
| 业务线 | 单一占位 | 多产品矩阵 + 统一控制面板 |
| 版本管理 | 未涉及 | 全部 Git 管理，天然支持历史追溯 |
| 特色 | — | 决策日志、成本核算、Prompt 模板库、增长实验、社媒运营体系 |
