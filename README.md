# 🧠 一人公司 AI 工作系统

> 用 Claude Code + GitHub 搭建可迭代的永续 AI 工作系统，让 AI 成为你的"第二大脑"。

## 这是什么

这是一套专为**一人公司 / 独立开发者 / Solo Creator**设计的工作系统框架。

它解决的核心问题是：

- **每次开 Claude Code 都要重复介绍自己和项目背景** → 用 CLAUDE.md 作为持久记忆
- **多个项目之间上下文切换混乱** → 总部仓库 + 项目仓库的分层架构
- **做完就忘，经验没有积累** → 决策日志 + 技能库 + 复盘机制
- **一人多角色没有流程** → 标准化的工作流和 Prompt 模板

## 架构概览

```
~/Documents/projects/
│
├── work-system/                # 总部仓库（战略 & 管理层）
│   ├── CLAUDE.md               # 🧠 全局入口 — Claude Code 自动读取
│   ├── 控制面板.md              # 📊 所有项目状态总览
│   ├── 个人定位.md              # 🎯 战略定位和方向
│   ├── 00-全局资源/             # 跨项目共享：技术栈、SEO、部署流程、Prompt 模板
│   ├── 01-项目模板/             # 新项目标准模板（复制即用）
│   ├── 02-运营中心/             # 选题、关键词、社交媒体、增长实验
│   ├── 03-商业/                 # 收入、成本、变现策略、市场机会
│   ├── 04-决策日志/             # 重要决策记录和复盘
│   └── 05-技能库/               # 最佳实践沉淀
│
├── project-a/                   # 项目仓库 A（代码 + 项目级文档）
│   ├── CLAUDE.md                # 项目专属上下文
│   ├── docs/                    # 项目文档
│   └── src/                     # 代码
│
└── project-b/                   # 项目仓库 B
    ├── CLAUDE.md
    ├── docs/
    └── src/
```

核心思想：**CLAUDE.md 是 AI 的记忆入口**。Claude Code 启动时自动读取当前目录的 CLAUDE.md，所以你在不同项目目录下工作时，AI 自动获取不同的上下文。

## 快速开始

### 1. 运行初始化脚本

```bash
git clone https://github.com/[your-username]/work-system-template.git
cd work-system-template
chmod +x init-work-system.sh
./init-work-system.sh
```

脚本会交互式询问你的信息，然后在指定目录生成完整的工作系统。

### 2. 填写核心文件

初始化完成后，花 20 分钟填写三个最重要的文件：

| 文件 | 内容 |
|------|------|
| `CLAUDE.md` | 你的业务全貌、项目列表、技术栈 |
| `控制面板.md` | 各项目当前状态 |
| `个人定位.md` | 你的目标和方向 |

### 3. 为已有项目添加 CLAUDE.md

```bash
cp work-system/01-项目模板/CLAUDE.md ~/Documents/projects/your-project/CLAUDE.md
cp -r work-system/01-项目模板/docs ~/Documents/projects/your-project/docs
```

编辑填入项目信息，提交到 Git。

### 4. 开始使用

```bash
cd ~/Documents/projects/your-project    # 做开发 → AI 读取项目上下文
cd ~/Documents/projects/work-system     # 做运营/战略 → AI 读取全局上下文
```

## 系统模块说明

### CLAUDE.md（核心）

系统的"灵魂文件"。分两层：

- **总部 CLAUDE.md**：写给 AI 的全局介绍，包括你是谁、做什么、有哪些项目、工作规则
- **项目 CLAUDE.md**：项目专属信息，包括技术细节、开发注意事项、当前状态

### 00-全局资源

跨项目共享的知识和规范：

- `技术栈.md` — 统一技术选型
- `SEO方法论.md` — SEO 通用策略
- `部署流程.md` — 标准部署流程
- `prompt模板库/` — 常用的 Claude Code prompt（新项目启动、功能迭代、Bug修复等）

### 01-项目模板

新项目的标准模板，包含 CLAUDE.md 和 docs/ 目录。每次新建项目时复制一份，保证结构统一。

### 02-运营中心

内容生产和增长相关：

- `选题管理/` — 博客内容的选题 → 写作 → 发布流水线
- `社交媒体/` — 人设策略、内容日历、素材库、数据追踪
- `关键词库.md` — 跨项目关键词研究
- `增长实验/` — A/B 测试和新渠道实验

### 03-商业

变现和财务：

- 收入总览、成本追踪、变现策略
- `市场机会/` — 新方向调研模板

### 04-决策日志

记录每个重要决策的背景、选项、结果。半年后回看，这是最有价值的资产之一。

### 05-技能库

在实际工作中积累的最佳实践，按角色分类：开发、SEO、运营。

## 工作流

| 场景 | 操作 |
|------|------|
| 日常开发 | cd 到项目仓库 → Claude Code 自动加载项目上下文 → 开发 → 更新迭代日志 |
| 战略规划 | cd 到 work-system → 更新控制面板和决策日志 |
| 新建项目 | 复制项目模板 → 填写信息 → 在控制面板注册 → 记录立项决策 |
| 内容生产 | 从关键词库选词 → 选题管理流水线 → 发布 |
| 社媒运营 | 从开发日常中提炼素材 → 按内容日历发布 → 周度复盘 |
| 踩坑总结 | 写入技能库对应分类 → 下次遇到同类问题 Claude 自动参考 |

## 设计原则

1. **CLAUDE.md 是唯一入口** — 一切从这里开始
2. **代码和管理分离** — 项目代码在各自仓库，全局管理集中在 work-system
3. **写给 AI 看** — 文档首先服务于 Claude Code 的理解
4. **最小启动，渐进生长** — 先搭骨架，在使用中填充内容

## 适合谁

- 用 Claude Code 做开发的独立开发者
- 一人公司创业者（产品 + 开发 + 运营一肩挑）
- 同时维护多个项目/网站的 Solo Maker
- 想让 AI 真正理解你的工作上下文的人
